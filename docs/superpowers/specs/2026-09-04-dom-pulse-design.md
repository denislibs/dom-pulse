# DOM Pulse — дизайн

Дата: 2026-09-04

## Цель

Оверлей-инструмент для браузера, который в реальном времени показывает, какие элементы DOM мутируют, как часто, кто это делает (файл и функция) и во что это обходится (форсированные reflow, сдвиги раскладки, объём изменений). Работает на любом сайте и с любым фреймворком, потому что слушает сам DOM, а не внутренности фреймворка.

Не является: инструментом для поиска «холостых» рендеров (это задача react-scan), записью истории с перемоткой, дашбордом здоровья страницы. Эти вещи могут появиться позже как отдельные режимы поверх того же `store`.

## Пользователь и сценарий

Разработчик подключает один скрипт (тег, букмарклет, консоль) на своей или чужей странице. Страница «оживает»: мутирующие элементы вспыхивают рамками, в углу HUD с цифрами, топом горячих элементов и топом источников. Разработчик находит элемент, который дёргают чаще всего, видит код, который это делает, и понимает, тянет ли это за собой reflow или layout shift.

## Сигналы стоимости

Каждая мутация привязывается к элементу и может получить метки:

1. **Форсированный reflow.** Патчатся геттеры и методы, вызывающие синхронный расчёт раскладки: `offsetWidth`, `offsetHeight`, `offsetTop`, `offsetLeft`, `clientWidth`, `clientHeight`, `scrollTop`, `scrollHeight`, `scrollWidth`, `getBoundingClientRect`, `getClientRects`, `getComputedStyle`, `scrollIntoView`, `focus`. Если вызов произошёл после мутации и до следующего кадра (`requestAnimationFrame`), фиксируется reflow: счётчик, интервал между записью и чтением, стек читающего кода.
2. **Сдвиг раскладки.** `PerformanceObserver({ type: 'layout-shift' })`. Прямоугольники сдвига сопоставляются с мутациями того же кадра по пересечению с `getBoundingClientRect` цели. Элемент получает суммарный вес сдвига и список сдвинутых областей.
3. **Объём.** Число добавленных и удалённых узлов с учётом поддеревьев, длина изменённого текста.

Не измеряется: время style recalc и paint. Из JS они недостоверны.

Итоговые метрики элемента: мутаций/с, reflow-вызовов после мутаций, суммарный layout shift, узлов затронуто.

## Диффы

Каждая запись `MutationRecord` нормализуется в событие с человекочитаемым диффом:

- **Атрибуты.** Старое значение из `attributeOldValue`, новое с элемента. Для `class` — списки добавленных и удалённых классов. Для `style` — изменённые свойства с старым и новым значением. Для остальных — старое и новое значение строкой.
- **Текст.** Старое из `characterDataOldValue`, новое из узла. Inline-дифф с выделением изменённого фрагмента; длинные строки обрезаются с обеих сторон вокруг изменения.
- **Дети.** Списки добавленных и удалённых узлов. Каждый узел сериализуется в подпись: тег, id, классы, число потомков. Если в одной записи удалён и добавлен узел с одинаковой подписью, событие помечается как «пересоздан».

События хранятся в кольцевом буфере, по умолчанию 500 последних.

Лента элемента: список его последних мутаций с диффом, стеком и метками стоимости. Открывается кликом по строке в HUD или Alt+клик по элементу на странице.

## Оверлей

Один `canvas` на весь viewport, `pointer-events: none`, `position: fixed`, максимальный z-index. Рисуются рамки элементов, мутировавших за последние 1,5 с, с плавным затуханием.

- Цвет по типу: зелёный — childList, синий — attributes, жёлтый — characterData. При нескольких типах за окно — цвет последнего.
- Насыщенность по частоте за последние 5 с. Выше настраиваемого порога (по умолчанию 20 мутаций за 5 с) рамка становится красной и держится, пока частота не упадёт.
- Reflow-метка — штриховая рамка. Layout shift — дополнительный бледный прямоугольник сдвинутой области.
- Перерисовка через `requestAnimationFrame`, только пока есть активные рамки. Координаты пересчитываются на scroll и resize.

Canvas — а не div на каждый элемент — чтобы рамки сами не порождали мутации и нагрузку.

## HUD

Панель в Shadow DOM, перетаскиваемая, позиция запоминается в `localStorage`. Сворачивается в бейдж с одной цифрой «мутаций/с».

Развёрнутый вид:

1. **Шапка.** Мутаций/с, reflow/с, суммарный CLS за сессию, спарклайн за 30 с. Кнопки: пауза, сброс, настройки, свернуть.
2. **Топ элементов.** Таблица, по умолчанию 10 строк, колонки: элемент (подпись), мут/с, reflow, shift, узлов. Сортировка по любой колонке. Клик по строке скроллит к элементу и подсвечивает его на оверлее. Повторный клик раскрывает ленту мутаций.
3. **Топ источников.** Файл и функция из стека, количество мутаций и reflow. Клик фильтрует таблицу элементов по источнику.

Фильтры: CSS-селектор включения и исключения, тумблеры по типам мутаций, порог минимальной частоты. HUD и canvas всегда исключены из наблюдения.

## Атрибуция

`MutationObserver` срабатывает асинхронно, стек в колбэке пуст. Поэтому патчатся точки записи в DOM: `appendChild`, `insertBefore`, `removeChild`, `replaceChild`, `append`, `prepend`, `replaceChildren`, `remove`, `insertAdjacentHTML`, `setAttribute`, `removeAttribute`, `toggleAttribute`, сеттеры `innerHTML`, `outerHTML`, `textContent`, `nodeValue`, `data`, `className`, `id`, методы `classList` (`add`, `remove`, `toggle`, `replace`), `style.setProperty` и сеттеры `style.*` через `CSSStyleDeclaration`.

Патч выполняет оригинал, затем в `try/catch` снимает `new Error().stack`, кладёт запись `{ target, stack, time }` в очередь. `observer` при обработке записи сопоставляет её с ближайшей по цели и времени записью очереди; несовпавшие записи получают стек `unknown`. Стек парсится в кадры `{ file, line, column, function }`; кадры самого DOM Pulse отбрасываются. Источник — первый пользовательский кадр.

## Архитектура

Модули, однонаправленный поток данных: патчи и наблюдатель пишут в `store`, оверлей и HUD только читают.

- `observer` — MutationObserver, нормализация записей в события, построение диффов.
- `attribution` — патчи точек записи, очередь стеков, парсинг стека.
- `cost` — патчи reflow-геттеров, подписка на layout-shift, подсчёт объёма, обогащение событий.
- `store` — кольцевой буфер событий, агрегаты по элементам (`WeakMap<Element, Stats>` плюс список для сортировки) и по источникам, скользящие окна частоты, подписка на изменения.
- `overlay` — canvas, отрисовка из `store`.
- `hud` — панель в Shadow DOM, чтение `store`, команды.
- `index` — сборка, публичный API.

Публичный API:

```ts
DomPulse.start(options?: {
  hotThreshold?: number;      // мутаций за 5 с для красной рамки, по умолчанию 20
  bufferSize?: number;        // размер кольцевого буфера, по умолчанию 500
  include?: string;           // CSS-селектор
  exclude?: string;
  topN?: number;              // строк в таблице, по умолчанию 10
});
DomPulse.stop();    // снимает патчи, наблюдатель, оверлей и HUD
DomPulse.pause();
DomPulse.resume();
DomPulse.reset();   // обнуляет store
```

Все патчи обратимы: `stop()` возвращает оригинальные дескрипторы.

## Подключение и сборка

- TypeScript, сборка esbuild.
- Два выхода: IIFE-бандл `dom-pulse.js` (тег `<script>`, букмарклет, консоль) и ESM для npm.
- Без runtime-зависимостей.

## Обработка ошибок

- Патч всегда сначала вызывает оригинал и возвращает его результат; наша логика после, в `try/catch`. Ошибка внутри DOM Pulse не меняет поведение страницы.
- Ошибки логируются в консоль один раз на тип, чтобы не заспамить.
- Если `PerformanceObserver` не поддерживает `layout-shift`, сигнал сдвига отключается, остальное работает.
- `stop()` идемпотентен и безопасен при частичной инициализации.

## Тестирование

- Юнит-тесты (Vitest + jsdom): нормализация записей и диффы (`observer`), парсинг стека и сопоставление с записями (`attribution`), подсчёт объёма и сопоставление reflow с мутациями (`cost`), кольцевой буфер, агрегаты и скользящие окна (`store`), обратимость патчей.
- Демо-страница `demo/index.html` с кнопками-сценариями: частая смена класса, массовая вставка через innerHTML, layout thrashing в цикле, сдвиг раскладки вставкой блока сверху, пересоздание списка. По ней вручную проверяются оверлей и HUD, каждый сигнал воспроизводим.

## Что вне объёма первой версии

Запись и перемотка истории, плитки «здоровья страницы» (FPS, long tasks, слушатели, детачнутые узлы), адаптеры к фреймворкам, экспорт данных, расширение браузера.
